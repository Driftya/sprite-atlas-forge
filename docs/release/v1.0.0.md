# Sprite Atlas Forge v1.0.0

Sprite Atlas Forge v1.0.0 is the first production-ready Windows desktop release.

## Highlights

- Detect sprites in transparent or border-connected PNG spritesheets.
- Edit sprite regions, connector metadata, tags, and approval state in the desktop editor.
- Repack atlases deterministically without rotation.
- Export Phaser JSON Hash, Unity 6 multi-sprite, and Godot 4 `AtlasTexture` formats.
- Save native `.saf.json` projects with dirty-state protection and undo/redo.

## Download and run

1. Download `SpriteAtlasForge-1.0.0-windows-x64.zip` and its `.sha256` file from the GitHub Release.
2. Verify the archive in PowerShell:

   ```powershell
   (Get-FileHash .\SpriteAtlasForge-1.0.0-windows-x64.zip -Algorithm SHA256).Hash.ToLowerInvariant()
   Get-Content .\SpriteAtlasForge-1.0.0-windows-x64.zip.sha256
   ```

3. Extract the entire ZIP to a writable folder.
4. Run `SpriteAtlasForge.exe`.

The application is an unpackaged, self-contained x64 Windows build. Keep the executable and all adjacent files together; the `.exe` is not a standalone single-file application. Windows 10 version 1809 or newer is required.

## Maintainer release procedure

The release workflow creates a draft GitHub Release from a version tag. For v1.0.0:

1. Confirm the working tree is clean and `ApplicationDisplayVersion` in the MAUI project is `1.0.0`.
2. Run the required verification locally:

   ```powershell
   .\eng\verify.ps1 -Configuration Release
   ```

3. Smoke-test the same self-contained publish used by CI:

   ```powershell
   dotnet publish .\src\Driftya.SpriteAtlasForge.ClientApplication\Driftya.SpriteAtlasForge.ClientApplication.csproj `
     --framework net10.0-windows10.0.19041.0 `
     --configuration Release `
     --output .\.artifacts\release-smoke-test `
     -p:RuntimeIdentifierOverride=win-x64 `
     -p:WindowsPackageType=None `
     -p:WindowsAppSDKSelfContained=true

   .\.artifacts\release-smoke-test\SpriteAtlasForge.exe
   ```

4. Commit and push the release changes, then create and push the annotated tag:

   ```powershell
   git tag -a v1.0.0 -m "Sprite Atlas Forge v1.0.0"
   git push origin v1.0.0
   ```

5. Wait for the GitHub **Release** workflow. It verifies the full solution, publishes the Windows app, records resolved dependencies, creates a ZIP and SHA-256 file, and attaches both to a draft release.
6. Download the draft assets, verify the checksum, extract the ZIP on a clean x64 Windows machine, and launch the application.
7. In GitHub, edit the draft release if needed and select **Publish release**.

For later releases, update both `Version` and `ApplicationDisplayVersion`, increment the integer `ApplicationVersion`, add `docs/release/vX.Y.Z.md`, and tag the same commit as `vX.Y.Z`.

## Known distribution limitation

This release uses a portable ZIP rather than a signed MSIX installer. Windows may show a reputation warning for a newly downloaded unsigned executable. Code signing and an installer can be added in a later release without changing the native project format.
